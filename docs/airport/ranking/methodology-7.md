# 如何用 Clash Verge 自带测速区分假延迟与真实可用性

> **直接结论：** Clash 面板绿色延迟数字很多时候只是单次探测包往返（甚至受本地缓存或入口快速应答影响），区分“假延迟”必须结合连续 3 次真连接 URL-Test 波动、实际浏览器首字节响应与 Cloudflare 丢包率。

## 识别 Clash “假绿色低延迟”的 3 步动作

1. **看连续两次测速波动**：间隔 10 秒点两次全分组测速。如果某个节点第一次显示 `35ms`，第二次变成 `Timeout` 或 `980ms`，说明该线路存在严重间歇性丢包，切勿选用。
2. **检查测试目标地址**：部分旧配置将延迟测试 URL 设为国内可达节点或过轻的网关，可改为 `https://cp.cloudflare.com/generate_204` 或 `https://www.gstatic.com/generate_204`。
3. **打开「连接」日志看真实耗时**：观察目标域名连接是否停留在握手阶段久久无下行字节增长。
